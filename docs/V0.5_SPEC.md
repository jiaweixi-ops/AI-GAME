# V0.5 Engineering Freeze

V0.5 has one gameplay objective: **reliably construct and verify one parameterized smelting module on the current save**.

## Required infrastructure

1. Version contracts: tool, digest, task, prompt, Blueprint IR, Contract Probe.
2. Budget layers: Global -> Task -> Batch -> Atomic. Batch execution never bypasses atomic/task charging.
3. Area lock and material reservation. A failed/cancelled batch releases unused claims.
4. Async verification with bounded deadlines and explicit `pending / verified / timeout / failed` states.
5. Structured failure fingerprints; unchanged environment + already-failed recovery is rejected for strategy review.
6. Replan frequency guard.
7. Formal metrics definitions.
8. Blueprint IR and deterministic smelting templates.

## Blueprint scope

Only 8/16/24/48 furnaces, single/double row, left/right input, north/south future expansion.

## Batch transaction

`reserve area -> reserve materials -> place idempotently -> checkpoint -> async operational verification -> release claims -> commit`.

On failure: **do not destructively roll back player entities**. Record the partial construction, release unused claims, persist evidence/fingerprint, and replan/reconcile from live state.

## Operational acceptance

A smelting module is complete only when fresh state proves expected entities exist, power margin stays above the configured minimum, requested product output reaches the configured minimum, budgets are respected, terminal locks/reservations are released, and failures cannot repeat the same proven-bad recovery under unchanged conditions.
